# VyaparSetu — Status
See `AI_CONTEXT.md` for the code map. 

**Roles (4):** applicant, officer, inspector, admin.
**Ports:** backend 5050, frontend 6060 (`CLIENT_ORIGIN` must be `http://localhost:6060`).
**Done:** login/register (real JWT), business profile, application create/submit, workspace load on login, logout clears cached data, AI assistant via backend (`GEMINI_API_KEY` in `backend/.env`), all 4 roles seeded.
**Also wired (v5 - security hardening):**
- Inspections: applicant now only sees inspections for their own applications; `:id` ownership/assignment checked for applicant and inspector.
- Officer can no longer use `?status=draft` to see other applicants' drafts (403 instead).
- Officer status-change (`PATCH /applications/:id/status`) is now scoped: can only act on applications assigned to them or unassigned ones (which they then claim); 403 if assigned to someone else.
- Mass assignment closed: business-profile PATCH now uses an explicit editable-field whitelist (`applicantId` can never be changed by the client); grievance creation whitelists applicant-supplied fields (status/priority/resolution can no longer be set at filing time).
- File upload: magic-bytes are now verified after upload (`file-type` package) - a `.pdf` that isn't really a PDF is rejected and deleted, closing the "spoofed extension/mimetype" gap. (Verified with a real test: genuine PDF passes, fake text-as-.pdf is rejected.)
- `express-mongo-sanitize` added globally (strips `$`/`.` operators from `req.body`/`req.query`).
- Result-set caps added on applications/grievances/inspections/users list endpoints (prevents one huge unbounded query).
- Server refuses to boot if `JWT_SECRET` is missing, short, or still the `.env.example` placeholder.
**Also wired (v6 - auth):**
- Change password (`POST /api/auth/change-password`): verifies current password, invalidates every other session for that account, returns a fresh token so the current tab keeps working. UI: Navbar -> profile menu -> "Change Password".
- Forgot / reset password (`POST /api/auth/forgot-password`, `POST /api/auth/reset-password`): generates a random reset token (SHA-256 hashed in DB, 1 hour expiry). Response never reveals whether the email exists. UI: "Forgot password?" link on the login form.
- Mobile OTP verification (`POST /api/auth/send-otp`, `POST /api/auth/verify-otp`): 6-digit OTP, hashed in DB, 10 min expiry. Runs automatically right after registration (skippable).
- Real logout (`POST /api/auth/logout`): JWTs now carry a `tokenVersion`; logging out (or changing/resetting password) bumps it on the user record, which instantly invalidates every previously issued token - not just clearing the browser's copy.
- **No SMS/email provider is wired up yet** (that's the "real payment/DigiLocker/SMS" item below) - OTPs and reset tokens are logged server-side and also returned in the API response when `NODE_ENV !== 'production'`, so the flow is fully testable today. Swap `deliverToUser()` in `auth.routes.js` for a real Twilio/MSG91/Nodemailer call later and every route keeps working unchanged.
**Also wired (v7 - tests, Docker, CI):**

**Also wired (v8 - payment, SMS/email, DigiLocker):**
- **Real payment ledger** (`backend/src/routes/payments.routes.js`, `models/Payment.js`): `POST /api/payments` charges the *server-computed* fee (never trusts a client-sent amount - it re-fetches each ApprovalType's fee by ID), persists it, generates a unique GRN, writes an audit entry, and notifies the applicant. `GET /api/payments/verify/:grn` is a public verification endpoint (same pattern as licence verify). `GET /api/payments/:id/receipt` streams a real PDF e-Challan with a QR code (verified visually: see backend/TESTING.md). This settles instantly ("sandbox" provider) rather than calling a live bank - there is still no live payment gateway (Razorpay/PayU/real MahaGRAS) wired up, since that needs a merchant account + KYC you'd set up separately; swapping in a real one only means changing the `settle()` function in that file. `MahaGrasPaymentModal.tsx` now calls this for real accounts (demo personas keep the old instant client-side simulation, clearly a sandbox already).
- **Real SMS/Email delivery** (`backend/src/utils/messaging.js`): Twilio for SMS, any SMTP provider (Nodemailer) for email. Both are wired into the OTP and password-reset flows. With no `TWILIO_*`/`SMTP_*` env vars set (the current state), everything falls back to a console log exactly as before - set the env vars in `.env` and delivery switches on with no code changes needed anywhere else. (Verified directly: calling `sendSms`/`sendEmail` with no keys configured falls back to console as expected.)
- **DigiLocker relabelled as Demo Mode**: the pull-documents modal now clearly says "Demo Mode" and explains that real integration needs a Requester registration at apisetu.gov.in (`DIGILOCKER_CLIENT_ID`/`SECRET` placeholders added to `.env.example`). This was **not** built as a working live integration - it needs external credentials only you can obtain - but it no longer misleadingly claims to be a live government API pull.
- 4 new tests in `payments.test.js` (server-side fee computation, ownership, invalid method, public verify + PDF receipt + ownership-gated download).
